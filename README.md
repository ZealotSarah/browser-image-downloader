# 微博、Instagram 和 X 图片视频下载

Chrome 扩展：一个右键入口，自动识别并下载微博、Instagram 和 X（Twitter）帖子的图片和最高规格完整视频；混合帖子两种都保存。支持微博 Live Photo、WebP 原文件及 PNG 副本，统一按平台、媒体类型、作者和帖子分类。详细行为见 [DESIGN.md](DESIGN.md)。

## 安装

安装包：[browser-image-downloader-0.4.7.zip](dist/browser-image-downloader-0.4.7.zip)。0.4.7 按媒体类型、博主及帖子分类；0.4.6 统一三站目录层级；0.4.4 补全原图地址并跳过重复下载；0.4.1 合并右键菜单；0.3.0 不包含 X；0.2.x 仅支持图片及 Live Photo。

1. 如果拿到的是 ZIP 安装包，先解压到一个固定文件夹；解压后的文件夹内应直接看到 `manifest.json`。安装后请保留该文件夹。
2. 打开 Chrome 的 `chrome://extensions`（Chrome 116 或更新版本）。
3. 打开右上角的“开发者模式”。
4. 点击“加载已解压的扩展程序”，选择解压后的文件夹。
5. 刷新已打开的微博、Instagram 和 X 页面。

## 使用

在微博、Instagram 或 X 帖子的内容、图片或播放器上右键，直接选择“下载这篇帖子的图片和视频”。扩展只注册这一个入口，不再分别显示图片/视频子菜单，也无需手动选择媒体类型。图片帖保存图片，视频帖保存视频，混合帖两种都保存。点击浏览器工具栏里的插件图标可查看最近一次任务结果及下载目录说明。

三站固定保存到 `Chrome 下载目录/平台/图片或视频/博主名称/帖子ID/`，平台名称分别为 `微博`、`Instagram` 和 `X`。Instagram、X 使用完整用户名，博主目录不追加用户 ID。每条帖子以帖子 ID 建立独立文件夹，同帖的图片和视频分别进入对应媒体类型下的帖子目录。WebP 原文件、PNG 副本及 Live Photo 动态文件随图片保存。旧目录设置和作者分类开关不再改变此结构。Chrome 不允许扩展通过下载 API 指定任意绝对路径；若要更换主下载位置，请在 `chrome://settings/downloads` 中更改 Chrome 的下载目录。若开启了“下载前询问每个文件的保存位置”，Chrome 仍可能逐张弹出保存对话框。

本插件通过当前微博页面的登录状态读取帖子图片数据。图片站可能拒绝没有微博来源信息的直接下载；插件会在隐藏页面中读取并验证文件，再交给 Chrome 保存。Live Photo 的静态图和动态文件使用同一序号，分别保存为 `.jpg` 等图片格式和 `.mov` 或 `.mp4`。无法取得明确地址或网站返回错误网页时会报告失败，不下载缩略图。微博修改页面结构或接口后，解析代码可能需要更新。目前支持 `weibo.com` 和 `www.weibo.com` 的网页，不包含移动版和搜索站点。

微博帖子数据的 `original` 字段有时仍指向 `/orj1080/` 缩放图；插件会改取同一图片的 `/large/` 地址，以获得完整尺寸。若该地址不可用，插件会报告下载失败。

若新浪图片站将原图请求转到微博的屏蔽占位图，插件会在保存前识别最终响应地址并跳过该文件。任务结果会单独显示跳过数量。

Instagram 支持 `www.instagram.com` 的普通图片帖子（`/p/`），包括轮播中的图片。插件优先使用当前登录会话读取帖子媒体接口，按像素面积选择每张图片最大的候选，直接获取轮播中的图片并跳过视频。相同尺寸优先选择 JPEG 地址，不改写签名地址。这是 Instagram 当前提供的最高分辨率候选，不保证是上传原件。

0.2.3 遇到 WebP 响应时，同时保存 WebP 原文件和同名同序号的 PNG 副本。PNG 使用浏览器解码后的完整尺寸、透明画布进行无损编码，不缩放、不再进行有损压缩，但无法恢复 WebP 已丢失的信息，也不保证保留原文件元数据。PNG 通常更大。两种文件分别统计下载结果，转换失败不会删除 WebP；其他图片格式不生成额外副本。

例如，一张 WebP 图片会保存为 `20261015_DeTzM24THMU_01.webp` 和 `20261015_DeTzM24THMU_01.png`。日期使用下载当天的本地日期。任务成功数量按文件统计，因此这张图片的两个文件全部下载成功时显示成功 2 个文件。

Instagram 媒体接口受限、超时或变更时，如果当前有播放器或为 Reels，直接报告失败，不下载封面代替视频；其他情况下可回退到页面 `srcset` 最大图，并明确提示画质回退及无法确认是否遗漏视频。接口返回的媒体缺少有效地址时计为失败。图片解析不处理头像、评论图片或视频封面。需要在浏览器中能正常看到帖子；私密或失效内容无法通过插件绕过访问限制。

0.2.2 修复了 Instagram 详情页没有 `article` 容器时无法定位帖子的问题，同时支持带作者名称的帖子链接，并排除详情页下方的推荐帖。

更新本地代码后，请在 `chrome://extensions` 中点击本插件的“重新加载”，再刷新微博或 Instagram 页面。

## 视频下载（0.3.0）

在微博或 Instagram 帖子的内容、图片或播放器上右键，选择“下载这篇帖子的图片和视频”，自动识别其中的视频。只处理右键所在的单篇帖子；混合轮播中的图片和视频都保存，视频封面不作为图片下载。Instagram 支持普通帖子和 Reels，暂不支持 Story；微博支持现有信息流和帖子详情，不包含独立 TV 播放页。

插件从当前登录会话取得帖子数据，在接口提供的完整视频候选中，按像素面积、帧率、码率依次排序选取最高档。不会将默认低清播放地址、Blob 播放地址、封面或未知分辨率文件当作最高规格视频，也不会因最高档下载失败自动换用低清版本。微博读取 `playback_list`，旧数据仅在 URL 的 `template` 参数给出明确宽高时使用；Instagram 读取 `video_versions`。

视频保存到 `Chrome 下载目录/平台/视频/博主名称/帖子ID/`。文件名为 `下载日期_帖子ID_序号.mp4`；插件弹窗显示所选分辨率和接口可用的帧率、码率。Instagram、X 视频直接交给 Chrome 下载；微博视频先在隐藏页面验证并生成 Blob 后保存，避免错误网页以 `.htm` 进入下载。微博视频逐个处理，临时文件资源在完成后释放；大视频需要等待完整读取和验证，读取超时为 3 分钟。

“最高规格”限定为接口当前提供、当前账号可访问的完整 MP4 文件，不等同于上传原件或平台所有编码中的最高档。DASH/HLS 分片、分离音视频的合并、DRM 和直播暂不支持；只有这些流或缺少明确规格时会报告不可用。如果平台另外提供更高清的分片流，本版不会合并下载。需要这些规格时应使用支持流合并的工具。扩展更新增加了微博视频 CDN 的站点权限，Chrome 可能要求重新启用扩展。

## X（Twitter）下载（0.4.0）

支持 `x.com`、`twitter.com` 及其 `www` 地址，在信息流或帖子详情的内容、图片、视频上右键，选择统一入口，自动保存全部可用图片和视频。只处理右键所属的单篇帖子；引用帖作为独立帖子数据保存，不将其媒体并入外层帖子。图片使用 `pbs.twimg.com/media/` 的 `name=orig` 地址，保留图片格式；若返回 WebP，同时保存原文件和 PNG 副本。视频及平台 GIF 的完整 MP4 候选按分辨率、可用帧率、码率排序，不下载视频封面。

图片保存在 `Chrome 下载目录/X/图片/用户名/帖子ID/`，视频保存在 `Chrome 下载目录/X/视频/用户名/帖子ID/`。文件命名、重名处理、三文件并发、失败重试和进度统计沿用现有规则。

扩展在页面启动时观察 X 网页自身的帖子 API 响应，复用页面的登录、代理和访问权限；不另行取得登录令牌，不复制请求凭据，不将帖子正文写入扩展缓存或存储。媒体数据在当前页面内存中最多保留最近 200 篇，离开或刷新页面后清空。请在加载或更新扩展后刷新 X 页面，并等待帖子加载完成；尚未取得数据时会提示刷新，不以低清网页流冒充最高规格。不支持已删除、当前账号不可见的媒体、直播、外链视频及 HLS/DASH 合并，也不保证取得上传原件。独立媒体弹层没有所属帖子卡片时，请回到帖子卡片右键。

## 原图补全与重复下载检查（0.4.4）

0.4.3 后该帖仍显示 1 个成功、3 个媒体地址不可用，说明图片原图地址未解析，尚未进入保存队列。0.4.4 优先读取混合媒体中的完整图片数据，避免不完整 `pic_ids/pic_infos` 遮蔽原图；转发摘要原图地址缺失时额外读取原微博详情，核对帖子 ID 和图片归属后补齐。详情读取失败会在弹窗显示具体原因，并区分“未解析地址”与逐文件下载失败。修复后的真实整帖下载仍待验证。

三站默认跳过已有成功文件：以站点、帖子、媒体种类、媒体路径及已知规格识别相同媒体，忽略过期时间等签名参数；再查询 Chrome 下载记录，只有已完成且文件仍存在才跳过。失败、文件已删除、缺少下载记录或规格升级时允许重新下载；WebP 和 PNG 分别检查，只补缺失的文件。若更改了保存目录，已有文件仍按媒体身份跳过，不自动复制到新目录。

扩展本地保存最近 2000 个成功媒体记录。升级时可尝试将最近一次任务的成功文件与 Chrome 下载历史匹配，补建记录，因此刚刚成功的视频可在重试时跳过；更早版本的其他任务无法保证识别。清除下载历史、卸载扩展或移动文件可能导致重新下载。识别依赖媒体元数据及 Chrome 文件状态，不进行文件内容哈希比对。

0.4.4 共 73 项自动测试通过，包括原微博详情补全、混合图片解析、已有文件跳过、删除后重下、签名变化、规格升级、PNG 补齐及失败重试。请重新加载扩展并刷新原帖后重试，查看识别到的图片数量及具体失败原因。

0.4.5 共 74 项自动测试通过。微博目录统一为 `微博/博主名称/图片`、`微博/博主名称/视频`，原微博目录设置及作者分类开关不再影响该结构。已有文件不迁移，成功文件去重继续生效；只有后续新保存的文件使用新目录。同名博主将进入同名文件夹，文件名中的帖子 ID 和 Chrome 重名处理仍保留。
