# 微博和 Instagram 图片视频下载

Chrome 扩展：右键下载微博原图（含 Live Photo 动态文件）、Instagram 单图或轮播图，以及两站帖子的最高规格完整视频。可设置 Chrome 下载目录下的子文件夹，并按作者分类。详细行为见 [DESIGN.md](DESIGN.md)。

## 安装

安装包：[browser-image-downloader-0.3.0.zip](dist/browser-image-downloader-0.3.0.zip)。`dist/` 中的 0.2.x 安装包仅包含图片及 Live Photo 下载；0.1.4 仅支持微博。

1. 如果拿到的是 ZIP 安装包，先解压到一个固定文件夹；解压后的文件夹内应直接看到 `manifest.json`。安装后请保留该文件夹。
2. 打开 Chrome 的 `chrome://extensions`（Chrome 116 或更新版本）。
3. 打开右上角的“开发者模式”。
4. 点击“加载已解压的扩展程序”，选择解压后的文件夹。
5. 刷新已打开的微博和 Instagram 页面。

## 使用

在微博内容或图片上右键，选择“下载这篇微博的全部原图”；在 Instagram 帖子的图片上右键，选择“下载这篇 Instagram 帖子的图片”。点击浏览器工具栏里的插件图标可查看最近一次任务结果并进入设置页。

微博默认保存到 `Chrome 下载目录/微博原图/博主名_用户ID/`，Instagram 默认保存到 `Chrome 下载目录/Instagram图片/用户名/`。两个子文件夹可分别在设置页修改。Chrome 不允许扩展通过下载 API 指定任意绝对路径；若要更换主下载位置，请在 `chrome://settings/downloads` 中更改 Chrome 的下载目录。若开启了“下载前询问每个文件的保存位置”，Chrome 仍可能逐张弹出保存对话框。

本插件通过当前微博页面的登录状态读取帖子图片数据。图片站可能拒绝没有微博来源信息的直接下载；插件会在隐藏页面中读取并验证文件，再交给 Chrome 保存。Live Photo 的静态图和动态文件使用同一序号，分别保存为 `.jpg` 等图片格式和 `.mov` 或 `.mp4`。无法取得明确地址或网站返回错误网页时会报告失败，不下载缩略图。微博修改页面结构或接口后，解析代码可能需要更新。目前支持 `weibo.com` 和 `www.weibo.com` 的网页，不包含移动版和搜索站点。

微博帖子数据的 `original` 字段有时仍指向 `/orj1080/` 缩放图；插件会改取同一图片的 `/large/` 地址，以获得完整尺寸。若该地址不可用，插件会报告下载失败。

若新浪图片站将原图请求转到微博的屏蔽占位图，插件会在保存前识别最终响应地址并跳过该文件。任务结果会单独显示跳过数量。

Instagram 支持 `www.instagram.com` 的普通图片帖子（`/p/`），包括轮播中的图片。插件优先使用当前登录会话读取帖子媒体接口，按像素面积选择每张图片最大的候选，直接获取轮播中的图片并跳过视频。相同尺寸优先选择 JPEG 地址，不改写签名地址。这是 Instagram 当前提供的最高分辨率候选，不保证是上传原件。

0.2.3 遇到 WebP 响应时，同时保存 WebP 原文件和同名同序号的 PNG 副本。PNG 使用浏览器解码后的完整尺寸、透明画布进行无损编码，不缩放、不再进行有损压缩，但无法恢复 WebP 已丢失的信息，也不保证保留原文件元数据。PNG 通常更大。两种文件分别统计下载结果，转换失败不会删除 WebP；其他图片格式不生成额外副本。

例如，一张 WebP 图片会保存为 `20261015_DeTzM24THMU_01.webp` 和 `20261015_DeTzM24THMU_01.png`。日期使用下载当天的本地日期。任务成功数量按文件统计，因此这张图片的两个文件全部下载成功时显示成功 2 个文件。

媒体接口受限、超时或变更时，图片菜单回退到页面 `srcset` 最大图并逐页展开轮播；开始提示和插件弹窗会明确说明画质回退。接口返回的图片缺少有效地址时计为失败。图片菜单不处理视频、Reels、Story、头像和评论图片；视频及 Reels 使用下述独立视频菜单。需要在浏览器中能正常看到帖子及其图片；私密或失效内容无法通过插件绕过访问限制。

0.2.2 修复了 Instagram 详情页没有 `article` 容器时无法定位帖子的问题，同时支持带作者名称的帖子链接，并排除详情页下方的推荐帖。

更新本地代码后，请在 `chrome://extensions` 中点击本插件的“重新加载”，再刷新微博或 Instagram 页面。

## 视频下载（0.3.0）

在微博或 Instagram 帖子的内容、图片或播放器上右键，选择“下载这篇微博的最高规格视频”或“下载这篇 Instagram 帖子的最高规格视频”。只处理右键所在的单篇帖子；混合轮播只下载视频，不下载封面和图片。Instagram 支持普通帖子和 Reels，暂不支持 Story；微博支持现有信息流和帖子详情，不包含独立 TV 播放页。

插件从当前登录会话取得帖子数据，在接口提供的完整视频候选中，按像素面积、帧率、码率依次排序选取最高档。不会将默认低清播放地址、Blob 播放地址、封面或未知分辨率文件当作最高规格视频，也不会因最高档下载失败自动换用低清版本。微博读取 `playback_list`，旧数据仅在 URL 的 `template` 参数给出明确宽高时使用；Instagram 读取 `video_versions`。

默认分别保存到 `Chrome 下载目录/微博视频/博主名_用户ID/` 和 `Chrome 下载目录/Instagram视频/用户名/`，视频目录可在设置中修改。文件名为 `下载日期_帖子ID_序号.mp4`；插件弹窗显示所选分辨率和接口可用的帧率、码率。直接交给 Chrome 下载，不将大视频整个读取到扩展内存。

“最高规格”限定为接口当前提供、当前账号可访问的完整 MP4 文件，不等同于上传原件或平台所有编码中的最高档。DASH/HLS 分片、分离音视频的合并、DRM 和直播暂不支持；只有这些流或缺少明确规格时会报告不可用。如果平台另外提供更高清的分片流，本版不会合并下载。需要这些规格时应使用支持流合并的工具。扩展更新增加了微博视频 CDN 的站点权限，Chrome 可能要求重新启用扩展。

## 本地检查

```powershell
node --test test
```

0.2.3 的 29 项图片相关测试覆盖帖子定位、高清候选选择、页面回退、WebP 原文件与 PNG 副本队列、转换失败及资源释放。图像转换测试使用浏览器图形 API 的模拟对象；真实 Chrome 中的 PNG 编码、像素一致性和完整下载流程仍需实测。

0.3.0 共 40 项自动测试通过，新增视频规格排序、混合媒体和转发微博、Reels 链接、视频消息路由、独立目录、直链下载和错误 MIME 拒绝测试。两站真实视频下载、声音完整性和账号可见规格仍需在 Chrome 实测。
